## What is meaningfully better now

The changes are substantive, not just wording edits.

The design now distinguishes **toward, away, negligible and intermediate** effects, with negligibility based on \(|S|\), not signed \(S\). It treats the whole-cell patch as a reference measurement rather than a causal ceiling, removes the impossible PCA-256 requirement, and no longer calls a weak block-0 patch an implementation failure. Lack of within-position leverage variation is now a diagnostic rather than an automatic reason to stop. Those all address the earlier problems directly. 

More importantly, **the off-trajectory arm now manipulates the same variable the probe measures.** It replaces an off-trajectory colour \(c\) with a previously absent colour \(c'\), consistently throughout the table. Thus:

\[
c:\text{present}\rightarrow\text{absent},
\qquad
c':\text{absent}\rightarrow\text{present}.
\]

The relevant start–intermediate–answer trajectory remains unchanged. The design separately tests the model’s response to the natural prompt change and to activation transplants. That is a substantially cleaner experiment than treating mathematical task irrelevance as evidence of computational irrelevance. 

**That is the experiment I would now emphasize:** can a reader recover a specific change in available table information even when the measured answer is insensitive to that change?

### A correction to the earlier smoke-test interpretation

The updated notes also narrow an important observation: J does name `green` at **L36 at `emit_colon`**, and at **L40 at `emit_think`**. The earlier “no colours at L40–44” observation applied to the particular `emit_colon` cell—not to all nearby positions.

The matched-cell comparison still matters, but the wider layer/position profile will keep us from mistaking localization differences for total reader blindness.

## 1. One real code hole: the integrity guard only checks engine construction

The new guard is useful. `NLAVerbalizer` marks the subject model after merging the SFT adapter, and `capture_stock()` checks that marker every time it runs.  

However, **`Engine` checks integrity in `__init__`, not in `forward`.** This leaves the following lifecycle unprotected:

```python
eng = Engine(subject)                 # Intact: constructor passes.
nla = NLAVerbalizer(subject, tok_av)   # Mutates and marks subject.
eng.forward(ids)                     # No new integrity check.
```

The existing engine retains references to the model’s modules, so constructing it before the merge does not isolate it from subsequent mutation. This is visible in the current implementation. 

`SecReplay` has the same constructor-only check; its later `build()` and `capture()` calls do not recheck the subject. 

**Fix:** check integrity at the point where the subject model is actually consumed—at least `Engine.forward()`, `SecReplay.build()` and `SecReplay.capture()`.

Add a test that constructs the engine while the model is intact, marks or mutates the model afterward, and then verifies that the next forward fails. The current tests check an **already marked model at construction**, which is why this lifecycle is not covered. 

This is a static code finding, **not evidence that any existing smoke result was contaminated**. Capturing everything before loading the NLA, as the repository instructs, avoids it; the guard should enforce that boundary even when orchestration changes.

## 2. Make the substitution probe test explicitly cross-fitted

There is a small ambiguity worth resolving before implementing the probe pipeline.

Section 3.3 says the membership probe is trained on **natural dev renders** and applied to substitution pairs. Section 3.4 lists natural renders **and substitution renders** in the activation collection. Collecting both is fine; the training/evaluation distinction needs to be explicit. 

For the first experiment, I would use:

> **Train on natural renders from other tables; evaluate both the original and substituted render of the held-out table with the same fitted probe.**

Let \(f_c^{(-t)}\) be the probe score for colour \(c\), fitted without any render from table \(t\). For a substitution \(c\rightarrow c'\), test:

\[
f_c^{(-t)}(h_{\mathrm{sub}})
-
f_c^{(-t)}(h_{\mathrm{original}})
<0,
\]

and

\[
f_{c'}^{(-t)}(h_{\mathrm{sub}})
-
f_{c'}^{(-t)}(h_{\mathrm{original}})
>0.
\]

In plain language: **the removed colour becomes less detectable, and the inserted colour becomes more detectable, using a probe that never saw that table.**

This is more informative than a pooled membership AUC alone. It checks whether the probe follows the particular edit rather than merely identifying table-level regularities.

The design already proposes this directional check; I would simply make its held-out training rule unambiguous. No extra model or elaborate method is needed. 

## 3. Scope the stir-cell no-op control to start-change pairs

This is an implementation detail, not a reason to redesign anything.

For **start-change pairs**, the stir positions precede the only changed token, so donor and recipient activations there should match.

For **table-substitution pairs**, the edited table is earlier in the prompt. Those stir activations can legitimately differ.

Therefore the bitwise stir-cell no-op assertion should apply to the start-change pairs, **not automatically to the new substitution pairs**. The revised design contains both pair types while retaining the original stir-cell control, so make this distinction explicit in the test dispatch.  

## My recommendations on the pending decisions

These are recommendations, not approvals or changes made to the repo.

| Decision | My recommendation |
|---|---|
| **SEC precision for L40+** | Adopt it for this pilot’s small-effect measurements. |
| **Reader snapshot in 001** | Include the small, separate snapshot after the reader-free outputs are saved and hashed. |
| **Chain split** | Keep the grouped 50/50 split for now; report surviving independent groups, not just pair counts. |
| **Reader-input bridge** | Test stock-versus-SEC reader stability on the snapshot before pooling reader scores with SEC assay results. |

The design already identifies all four issues. 

### Why SEC now

The committed regime checks motivate the switch: the reported numerical sensitivity under RHUT is close enough to the proposed small-effect thresholds to complicate negative conclusions, whereas the SEC upper-stack replay has a much smaller measured floor. The new design makes this a pending decision rather than silently treating it as already approved. 

I would still describe the SEC results as results under that replay regime. More precise arithmetic does not remove the need to check correspondence with the stock activations supplied to the readers.

### Why include the reader snapshot

The proposed separation is sensible: finish and hash the reader-free outputs first, then inspect a small predetermined sample. Reader outputs do not select or change the assay. 

My suggested refinement is to choose **ten distinct tables**, rather than simply ten pairs that could include several partners from one table. Include original and substituted activations, and a natural same-cell shuffled-activation control alongside no activation.

That would let the snapshot answer something concrete:

> When the activation changes from “table contains \(c\)” to “table contains \(c'\),” does the reader’s description change accordingly?

This is a sharper demonstration of activation sensitivity than merely comparing a real input to an empty injection.

### Why not shrink the chain test split yet

The design reports only **20 step-sequence groups** before competence gating. Numerous pairs generated from a few sequences do not create numerous independent tests of generalization. 

I would keep the split and allow chain to remain a secondary pilot if support is thin. Changing to 70/30 merely to obtain more dev pairs risks leaving a very weak final test. The gating results should tell us whether chain supports the intended analysis.

## What 001 can now genuinely establish

The revised pilot can produce an interpretable combination of observations:

\[
\underbrace{\text{membership probe follows }c\rightarrow c'}_{\text{decoding evidence}}
\]

together with

\[
\underbrace{\text{small natural-prompt and transplant effects}}_{\text{bounded influence on the specified answer}},
\]

and then, in the separate snapshot,

\[
\underbrace{\text{reader tracks—or misses—the same change}}_{\text{reader evidence}}.
\]

A result of that form would support:

> **This reader reports information whose tested change is decodable at the cell but has little measured influence on this answer.**

It would not establish that the information is outside the workspace, globally unused, or irrelevant to every possible consumer. But it would directly address the question the project now asks, without relying on those stronger interpretations.

**Bottom line:** the earlier design issues have largely been addressed. Fix the runtime integrity check, make the held-out substitution scoring and pair-specific controls explicit, and move to the implementation and smoke stage. The next useful update should be a handful of inspectable experimental cases—not another expansion of the methods list.
