## What I would preserve

The source code implements several safeguards we previously only discussed.

**The reader/label separation is enforced in tests.** `test_import_boundary.py` checks transitive imports, including imports inside functions, to prevent label modules from reaching reader code. That does not make the causal assay assumption-free, but it does protect against accidentally using J/NLA machinery to construct the reference. 

**The swap is explicit and inspectable.** `Swap1D` implements donor-coordinate replacement:

\[
h'=h+\left(t-u^\top h\right)u,
\qquad t=u^\top h_{\mathrm{donor}},
\]

with the write performed outside autocast and the realized displacement recorded afterward. The tests check coordinate readback, which rows changed, and preservation of earlier positions/layers.  

**The margin scorer handles complete answers.** It scores every token of accepted spellings and reconstructs the intervention for each teacher-forced continuation, allowing the donor to be captured at the matching sequence length. That directly addresses the earlier prefix-scoring and sequence-length problems. 

I would keep this architecture. The main remaining work is clarifying what its measurements justify.

## 1. Fix the signed “small effect” criterion

This is the clearest remaining labeling error.

The amendment and Design 001 use

\[
S<\epsilon'
\]

to identify small full-cell effects, with \(\epsilon'=0.05\). But \(S\) is signed. A patch with

\[
S=-0.8
\]

satisfies that inequality despite causing a large change in the **opposite** direction. The same issue affects the proposed within-position variation test.  

For a negligible-effect category, the relevant condition is closer to

\[
|S|<\epsilon',
\]

with uncertainty or numerical resolution considered. Keep three outcomes distinct:

**toward the intended counterfactual**, **away from it**, and **approximately unchanged**.

For a population-level claim that an effect is negligible, use an equivalence interval rather than merely failing to find a positive effect:

\[
\operatorname{CI}(\mathbb E[S])
\subset(-\epsilon',\epsilon').
\]

There is already an `equivalence()` helper in `stats.py`; it should be connected to the relevant group-level analyses. A group-level equivalence result still should not be turned into an absence label for every individual item. 

### Also: a full-cell patch is a reference, not a guaranteed ceiling

The amendment flags cases where a one-dimensional edit exceeds the full-cell edit. Good—but that pattern is not uniquely a patching illusion, and a small full-cell effect does not rule out influential components. 

A simple counterexample:

\[
f(h_1,h_2)=h_1-h_2.
\]

Replacing \((0,0)\) with donor state \((1,1)\) changes nothing:

\[
f(1,1)-f(0,0)=0.
\]

Replacing only the first coordinate changes the output by one:

\[
f(1,0)-f(0,0)=1.
\]

The full replacement bundled two effects that cancelled.

**For 001, “full-cell patch effect” is a valid measurement. For later labels, “small full-cell patch effect” should not automatically become “this cell/content is not needed.”**

## 2. Make the off-trajectory intervention a core part of the pilot

Design 001 already identifies the problem in §9.1: changing the start colour changes the input, intermediate and answer together. That patch cannot establish whether a particular *off-trajectory* colour influences the answer. The proposed off-trajectory edit arm is the right response. 

I would include it before treating brew as a source of decodable-but-low-influence content.

Suppose the relevant trajectory is

\[
s\rightarrow z\rightarrow a.
\]

Choose a table row with key \(k\) that this trajectory never visits, and change

\[
T(k)=b
\quad\longrightarrow\quad
T(k)=b'.
\]

Keep the relevant trajectory unchanged.

Now we have a specific question:

> Does the activation encode this off-trajectory binding, and does transferring its changed state influence the answer?

There are two separate tests:

**Natural prompt change:** Does changing the irrelevant row leave the model’s answer behavior approximately unchanged?

**Activation intervention:** Does transplanting the resulting activation difference also leave it approximately unchanged?

The mathematical task’s answer being invariant does not establish that the model’s computation is invariant.

### Match the decoded variable to the intervention

The current probe target is whether a colour is present off-trajectory versus absent from the table. That is a reasonable **table-membership decoding** test, but it is not necessarily the same variable as the result stored in one edited row. 

For the stronger experiment, define the target explicitly as something like

\[
z_{\mathrm{off}}=T(k),
\]

rather than merely “colour \(b\) is somewhere in the prompt.”

Otherwise the probe and intervention could concern different facts.

Because the correct answer is unchanged, this arm must not divide by a counterfactual answer gap that is zero. Use the proposed absolute answer-probability change and distributional change, with a predeclared negligible-effect bound. The design already recognizes this.

## 3. The proposed PCA dimensionality is not feasible as written

Design 001 proposes approximately **230 dev renders**, followed by five-fold grouped cross-validation and **PCA to 256 dimensions inside each training fold**. 

That cannot work as a 256-dimensional empirical PCA on that sample.

For a centered training matrix

\[
X_{\mathrm{train}}\in\mathbb R^{n_{\mathrm{train}}\times d},
\]

\[
\operatorname{rank}(X_{\mathrm{train}})
\le \min(d,n_{\mathrm{train}}-1).
\]

An outer training fold contains fewer than 230 rows, and inner folds contain fewer still. Per-colour exclusions reduce some datasets further.

**Fix:** choose a smaller rank or cap it separately inside every training fold:

\[
r=\min(r_{\mathrm{requested}},d,n_{\mathrm{train}}-1).
\]

Also assert that every binary probe fold contains both classes.

This is a **planned-pipeline issue**, not a failure of the existing tests: Experiment 001’s code has not yet been written. I would keep the first probe pipeline simple—regularized logistic regression, with a modest PCA rank only if it helps on dev data—rather than introduce another large tuning surface.

## 4. Two stop rules currently treat hypotheses as implementation invariants

### A. Low L0 patch effect does not necessarily mean the engine is broken

The design correctly includes an **input-embedding replacement** as an exact anchor. When the pair differs only at that input token, replacing that embedding should reproduce the donor computation.

But it also treats a sufficiently small **block-0 output patch** at the changed token as an engine failure. 

These are different interventions.

By the end of block 0, information from the changed input may already have influenced other positions or state. Replacing only the source token’s block output does not replace those other effects.

Therefore:

- Failed embedding-anchor or self-patch checks are implementation alarms.
- A small block-output patch is a localization result unless another test shows the implementation is wrong.

I would remove the unconditional “engine broken” conclusion from the L0-effect threshold.

### B. Uniform full-cell leverage does not eliminate content-level selectivity

The design stops label construction if no position has sufficiently mixed high/low full-cell patch shares. 

That is useful diagnostic information, but too strong as a universal stop rule.

Every decision cell could have a large full-cell patch effect because it carries answer-related information. **Within those same cells**, some decoded claims could concern the intermediate and others an irrelevant table entry.

So:

\[
\text{little variation in whole-cell leverage}
\not\Rightarrow
\text{little variation in claim-specific influence}.
\]

I would interpret this outcome as “whole-cell leverage will not supply the desired contrast.” Then check the off-trajectory content intervention before abandoning the causal comparison.

## 5. Precision matters most exactly where this project wants to claim a null

The regime check reports that RHUT-style float32 residuals with bf16 matrix multiplications differ from the true-float32 upper-stack replay by up to **3.3% of the whole-run gap** on the tested edits. It also reports substantially smaller responses to tiny perturbations under the true-float32 replay. The status appropriately limits these observations to a very small set of examples. 

The important relationship is:

\[
\epsilon'=5\%
\]

for “small influence,” while the accepted regime discrepancy can itself approach that scale.

A regime check passing “difference below 5%” is therefore **not sufficient to establish that a 5%-threshold label is stable**.

My recommendation matches the concern already raised in Design 001:

**Use the current regime for broad leverage exploration if necessary; use the true-float32 replay, or explicit cross-regime agreement, for the small-effect decisions in 002.** 

There is also a measurement bridge to check. Reader inputs are captured from stock bf16 runs, while causal assays use the modified precision regime. That is explicitly documented, not hidden. Before claiming matched-state reader-versus-causality results, check whether relevant reader scores and intervention conclusions are stable across those capture regimes.

## One practical hazard in the reader code

`NLAVerbalizer` **merges the SFT adapter into the supplied base model in place**, then attaches the RL adapter. The source explicitly warns to capture first. Meanwhile, `capture_stock()` disables an attached adapter, but disabling an adapter cannot undo a previously merged SFT update.  

I am **not saying the current smoke run is contaminated**. The risk is future orchestration that reuses the model after NLA initialization.

I would enforce one of these boundaries: capture all subject-model activations before loading the NLA, or use a separately loaded model for NLA inference. A test that subject-model logits remain unchanged across reader orchestration would make this harder to get wrong.

## What I would do next

**Keep the architecture and the narrowed scope. Amend Design 001 rather than reopen the whole project.**

The immediate changes are: use magnitude-aware small-effect criteria; add the off-trajectory content intervention; fix the probe rank; and distinguish genuine implementation invariants from empirical localization predictions.

Then run a pilot whose output is a small, inspectable set of cases answering:

> **What changed in the prompt? What can be decoded at this cell? What did the independent edit change downstream? What did each reader say?**

For the reader comparison, preserve the actual checkpoint contracts: compare NLA with J/R at L42, and Oracle with J/R at L40/L44. The amendment already separates Oracle’s off-contract L42 arm; do not pool it back in for convenience. 

**The most informative first result is not a reader ranking. It is an explained disagreement:** for example, a case where the NLA names `green`, J does not, and independent tests distinguish whether that name tracks the intermediate, the input/table information, or an answer-correlated signal.

The repository now has much of the machinery needed to investigate that. The remaining challenge is ensuring that the label says exactly what the intervention measured—not more.
