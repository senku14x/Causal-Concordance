Abstract
Recent interpretability methods have proposed to
translate LLM internal representations into natu-
ral language descriptions using a second verbal-
izer LLM. This is intended to illuminate how the
target model represents and operates on inputs.
But do such activation verbalization approaches
actually provide privileged knowledge about the
internal workings of the target model, or do they
merely convey information about the inputs pro-
vided to it? We critically evaluate popular verbal-
ization methods and datasets used in prior work
and find that one can perform well on such bench-
marks without access to target model internals,
suggesting that these datasets are not ideal for
evaluating verbalization methods. We then run
controlled experiments which reveal that verbal-
izations often reflect the parametric knowledge of
the verbalizer LLM that generated them, rather
than the knowledge of the target LLM whose acti-
vations are decoded. Taken together, our results
indicate a need for targeted benchmarks and exper-
imental controls to rigorously assess whether ver-
balization methods provide meaningful insights
into the operations of LLMs.1
1. Introduction
LLM representations are opaque. Can we understand them
by translating them to natural language? This sort of verbal-
ization—decoding activations into natural language—has
been a recent focus in interpretability research (Ghande-
harioun et al., 2024; Pan et al., 2026; Chen et al., 2024).
Verbalization uses an auxiliary LLM as a verbalizer to trans-

late the activations of a target LLM into a natural language

derstand “an LLM’s computation” (Ghandeharioun et al.,
2024), allowing one to answer “open-ended questions about

Recent work has investigated verbalization techniques for
characterizing the inner workings of LLMs (Ghandeharioun
et al., 2024; Chen et al., 2024) and identifying harmful
knowledge they encode (Chen et al., 2024; Pan et al., 2026).
Such techniques are exciting because verbalization may
offer natural language explanations of privileged knowledge
into otherwise opaque model behavior. Knowledge about
the state of an agent is considered privileged when it is not
directly observable (Alston, 1971). In the context of LLMs,
we consider information privileged when it is accessible by
inspecting internal states (e.g., model activations) and not
via black-box access (like prompting).
To characterize an LLM’s behavior, the verbalizer may ei-
ther communicate privileged information about the target
LLM, information already available in the input we have
given this model to process, or a combination of the two
(Figure 1). If it tells us only about the input, verbalization
is of questionable utility from an interpretability perspec-
tive; we already have access to this. Further, verbalizers are
LLMs with implicit world knowledge which they may draw
on when decoding model activations, making it difficult
to disentangle whether generated descriptions reflect the
knowledge from the target or the verbalizer LLM. Put an-

We offer evidence that existing verbalization techniques
may yield unfaithful descriptions using two tasks: feature
extraction (Hernandez et al., 2024) and factual recall (Meng
et al., 2022; Allen-Zhu & Li, 2024).2 First, we establish that
some benchmarks previously used to evaluate verbalizers
(Ghandeharioun et al., 2024; Pan et al., 2026) do not require
the verbalizer to use privileged information. Instead, the ver-
balizer can perform well on these tasks without any access
to target model internals, so long as the target and verbal-
izer models have similar parametric knowledge. We then
design a controlled task to verify whether verbalizers reli-
ably access privileged information, finding that they often
reflect the verbalizer’s knowledge instead of target model’s
activations.
We show in Section 3 that there exist verbalization evalua-
tions that cannot support conclusions about target model ac-
tivations because verbalizer LLMs correctly answer prompts
using only input text—without access to activations. These
evaluations can only diagnose whether information about
the input is removed during processing and not whether the
target model adds its world knowledge to the response. In
Section 4 show that target model activations contain suf-
ficient input information for the verbalizer LLM to invert
target model activations and recover input prompts, sug-
gesting this is a viable alternative explanation for ostensible
verbalization “success”. For these tasks, information about
the input is not removed from the activations—making them
unsuitable for interpreting verbalization behavior.
In Section 5, we introduce a new evaluation task to study the
reliability of accessing privileged knowledge when knowl-
edge is misaligned between the verbalizer and target models.
This analysis suggests that verbalizers may only describe
knowledge added to the target model if both models have
similar parametric knowledge. When the verbalizer contains
knowledge the target model does not have, the verbalizer is
too expressive and fabricates answers using its own knowl-
edge, indicating that the expressiveness of a verbalizer may
lead to unfaithful explanations of target model activations.
Our results underscore the challenges of evaluating ver-
balization for interpretability. Verbalization is appealing
because it offers natural language descriptions of model be-
havior. If privileged knowledge is not used during verbaliza-
tion, however, then we cannot be sure that the verbalization
outputs are telling us anything about the target model in
particular (beyond the input text that it has processed); this
renders such evaluations uninformative. Consequently, with-
out evaluative tasks that control for the source of knowledge,
we cannot draw firm conclusions about model behavior.

3. Does Verbalization Convey Privileged
Information?
Does the verbalizer even need target model activations for
existing verbalization evaluations, or can it answer xprompt
using the original xinput alone? If verbalizers can perform
well on an evaluation dataset without access to target model
activations, this suggests this dataset is not measuring what
we care about; a common phenomenon in NLP (Goyal et al.,
2017; Kaushik & Lipton, 2018; McCoy et al., 2019). We
assess if the datasets used in prior verbalization work are
appropriate in this respect.

5. Are Generated Descriptions Faithful?
We have shown in Sections 3 and 4 that verbalization may
be explaining features of the input text, not activations, at
least as evaluated on the feature extraction task.10 Next we
show that verbalizers may not answer prompts correctly
unless they can answer them from the input text alone.
Our experiments test verbalizers using prompts that require
world knowledge; ideally M2 would tell us about the world
knowledge of the target model M1. But M2 is itself an
LLM with world knowledge of its own, so it can answer
prompts without access to M1 internals. Therefore, ver-
balizers may respond to a prompt by drawing on M1’s
knowledge, by drawing on M2’s knowledge, or by some
combination. To disentangle these possibilities, we consider
multiple setups where M1 is finetuned on a novel dataset,
imbuing it with knowledge unknown to M2.

We introduce PersonaQA, a dataset containing attributes
and texts of fake individuals. Because these individuals

6. Related Work
Mechanistic interpretability (Saphra & Wiegreffe, 2024)
seeks to characterize the inner workings of LLMs.15 Our
work is most relevant to techniques that investigate mapping
internal activations to tokens (nostalgebraist, 2020; Belrose
et al., 2023; Pal et al., 2023; Yom Din et al., 2024; Langedijk
et al., 2024; Gottesman et al., 2025), and in particular tech-
niques that map activations to natural language descriptions
(Bills et al., 2023; Mousi et al., 2023; Ghandeharioun et al.,
2024; Chen et al., 2024; Pan et al., 2026), rather than single
token distributions (nostalgebraist, 2020).
Another line of related work asks whether models can truly
introspect privileged information, with mixed findings (Ka-
davath et al., 2022; Song et al., 2025a;b; Binder et al., 2025).
The present effort is novel as our focus is on verbalization
methods that access activations to investigate whether these
activations offer such privileged information.
Finally, recent efforts have investigated the faithfulness
(Jacovi & Goldberg, 2020) of natural language explana-
tions with respect to model behaviors (Hase et al., 2020;
Atanasova et al., 2023), specifically for explanations like
Chain-of-Thought (CoT) reasoning (Turpin et al., 2023; Lan-
ham et al., 2023; Lyu et al., 2023; Arcuschin et al., 2025)
and individual neurons (Antverg & Belinkov, 2022; Bills
et al., 2023; Singh et al., 2023; Huang et al., 2023). These
works have shown that such explanations may provide unre-
liable descriptions of LLM behavior (Antverg & Belinkov,
2022). Our work is novel in that it is the first to investigate
the faithfulness of verbalization techniques, offering a rigor-
ous analysis of the reliability of explanations sourced from
such techniques.
7. Limitations
Our work has some limitations, including our reliance on
QA tasks and use of relatively small models. Specifically,
we stress test verbalization on datasets used in prior work
(Pan et al., 2026; Ghandeharioun et al., 2024) and introduced
new QA tasks for evaluation. We do experiment with other

8. Conclusions
There has been nascent interest in verbalization, i.e., gen-
erating interpretable natural language descriptions of the
internal activations of a target model. Our findings high-
light some open questions about such techniques and the
datasets that have been used to evaluate them. For example,
for the feature extraction task commonly used, we showed
that we can achieve strong performance without access to
target model internals. Such evaluations may therefore only
be useful as a diagnostic to assess of input information is
encoded in activations; it may not tell us anything else about
the target model, so care must be taken when choosing
evaluative tasks to interpret model behaviors.
Furthermore, we found that generated descriptions may of-
ten reflect the world knowledge of the LLM used for verbal-
ization more than the internal knowledge of the target LLM.
Controlled evaluations reveal that verbalizers may fail to ac-
cess privileged knowledge if the target and verbalizer have
mismatches in knowledge. Future work might investigate
how to extract information from target LLMs that the ver-
balizer LLM may not possess, by using methodologies that
extract knowledge directly from model activations, rather
than textual inputs.
Future work might focus on designing evaluations that em-
phasize general QA knowledge less and knowledge known
to be specific to the target model more (e.g., relying on fine-
tuning the latter, or on time cut-offs that naturally realize
such exclusive parametric knowledge). Or, for example, one
might construct a dataset that comprises instances where
M1 and M2 offer different responses when fed the same
input. Then if M2 changes its response given the activa-
tions of M1, this might be an indicator that M2 is in fact
faithfully inspecting M1’s knowledge.
In sum, our findings show that the chosen evaluative task
has strong implications with respect to our ability to assess
whether privileged information has been communicated.
Without carefully choosing an evaluation, it is difficult to
measure what the verbalizer is describing: The target model,
or its own parametric knowledge. None of this is to say that
insights cannot be obtained by using verbalization methods;
we think they offer an intuitive and potentially promising
tool to describe opaque activations. But we caution that
we need controlled evaluations for measuring verbalization
ability to truly evaluate what it is that verbalizers are in fact
(hopefully faithfully) telling us.
Impact Statement
Our work investigates the faithfulness of decoding activa-
tions into natural language using promising interpretability
methods, specifically to understand whether the explana-
tions elicited by a verbalizer LLM may appropriately rep-
resent the target model’s knowledge. We hope that the
evaluation of such interpretability methods in our work
can increase efforts in crafting more reliable evaluative ap-
proaches, encouraging more faithful methods for inspecting
activations and providing more honest interpretations of
opaque LLMs.

To implement LIT, we reuse existing code18 from Pan et al. (2026) and use default hyperparameters, changing code

Patchscopes.
To implement Patchscopes (Ghandeharioun et al., 2024), we use the original data generation code
from the GitHub repository 19 for the feature extraction experiment. For the method reimplementation, we use nnsight
(Fiotto-Kaufman et al., 2025) to gather a single activation and patch the new activation into the inference pass of the
verbalizer LLM. All other hyperparameters are consistent with the original Patchscopes work.
B.2. Evaluation
LIT.
For LIT (Pan et al., 2026), we train a verbalizer to decode activations from ℓ= 15 and we calculate performance for
the first 15 layers of Llama3 individually, with the exception of the first layer (Llama3 has 32 layers, so layer numbers 1 -
15). We then average accuracy across the layers for a final score. In the main paper, we use the same verbalizer trained on
ℓ= 15 to evaluate the other layers, which is consistent with prior work.
Patchscopes.
In our Patchscopes evaluation, we focus on a setting that is less compute-intensive than but still
consistent with prior work (Ghandeharioun et al., 2024; Pan et al., 2026). To compare against LIT, we only consider the
first 15 layers for Patchscopes. In Ghandeharioun et al. (2024), they consider all combinations of source ℓ∈[1, ..., L]×
target ℓ∗∈[1, ..., L∗], which implies that for each source layer, the source layer is patched into all target layers. Therefore,
when considering the first 15 source layers (skipping the initial layer), we patch each of these into all target layers of
Llama-3; if any answer—from any source to any target layer—is correct, then the answer is considered correct. Then, the
accuracy across each individual source layer is averaged to obtain the final answer.
This Patchscopes approach is exhaustive, and for feature extraction across only six datasets, requires 15 · 32 runs per
individual task, or 2880 total runs. Not including PersonaQA and related datasets (and baselines), this would total 10,000+
evaluations. As noted in the main paper, we originally tested with layers 1 - 32 for Llama3 and found that performance
was worse when averaging over all source layers; so to save compute, we evaluate over half of the layers, which is again
consistent with prior work.
Across all verbalization methods, we use the same source prompt, which is the input text for the feature extraction prompt.
Ghandeharioun et al. (2024) samples additional subjects for their input context to get their results; we do not, as we only use
the raw feature extraction prompt, so our performance differs slightly from the results in the paper.

With the newly updated code, our original codebase ran each of the Patchscopes run individually on separate GPUs
for each input and layer combination, rather than linearly. Here, we show the results for our released code when the

D. Inversion Training Details And Outputs
D.1. Inversion Details
Fidelity of input reconstructions.
To invert an activation matrix hℓ, we train Mrec = Llama3-8B-Instruct
(Llama3) or Mrec = Ministral-8B-Instruct (Ministral) by inserting activations into the input of Mrec of
Llama3 and using the original prompt as the label. For implementation, we use existing code from LIT (Pan et al., 2026)
but use the input as the target so that the model learns to reconstruct this from activations. We choose ℓ= 15 since (Pan
et al., 2026) has previously verbalized activations from this layer, intuiting that task-specific information may be localized in
the middle layers.
To invert a single activation hℓ
i, we train both types of Mrec. We use the vec2text20 implementation to train Mrec =
T5-Base for inversion, taking hyperparameters from Morris et al. (2023). For inversion with Mrec = Llama3, we
implement reconstruction by inserting hℓand taking a loss over the input text, to learn to invert. We provide more details on
this implementation in Appendix D.3 and Appendix D.4.
D.2. Inversion Evaluation
For evaluating inversion, we adopt as our metric BLEU (Papineni et al., 2002), following prior work on inversion (Morris
et al., 2023). We also note that the measured inversions are for out-of-domain instances compared to the data used to train
the inverter Mrec. Out-of-domain inversions have been shown to result in lower performance (Morris et al., 2023).
Quantitative results.
We report inversion results in Appendix Table 12, using feature extraction as our evaluation task.
Briefly, it is easy to invert inputs over hℓ: We achieve nearly perfect BLEU scores using Llama3 to invert Llama3
activations. Appendix Table 13 provides examples. When using Llama3 or Ministral to invert hℓ
i, we achieve much
lower BLEU scores, doubling the score when reconstructing with T5-Base. T5-Base is more accurate, agreeing with
findings from Morris et al. (2023). Though inverting hℓ
i shows a relatively low BLEU score, a qualitative inspection shows
that reconstructions tend to capture the same structural similarity, though oftentimes key words are missed. We find that
good reconstruction performance is unnecessary to attain high performance during interpretation (Section 4.1), as we still

D.3. Inverting hℓ
To invert an activation matrix hℓ, we train Mrec = Llama3 using the Adam optimizer (Kingma & Ba, 2015) with lr = 2e−4
and an effective batch size of 128. We train with LoRA (Hu et al., 2022) with four A100s, training for approximately one
epoch (we cut training short because we find that the model learns to invert very quickly based on the validation loss, and
that an entire epoch may take several days). Specifically, the LoRA parameters are: rank r = 16, α = 32. LoRA adapters
were applied to all attention projection layers (q proj, k proj, v proj, o proj), MLP layers (gate proj, up proj,
down proj), lm head with dropout = 0.05. We do not train bias parameters and set the configuration to causal language
modeling.

E. Cross-model Results
Cross-model quantitative outputs.
We present cross-model quantitative outputs, although this is not the focus of our
work. However, prior verbalization methods have implied that it may be possible to verbalize activations from other models
(Ghandeharioun et al., 2024), so we analyze whether it is possible to do cross-model verbalization. For this we set M2 =
Ministral21 (Mistral, 2024), which is a similarly-sized model, while we keep M1 the same. Including a verbalizer LLM
M2 that is different from M1 allows us to interpret whether verbalization behavior is consistent across model families. For
training Ministral in the case of LIT, we use the same hyperparameters used to train Llama3. For Patchscopes,
we train an affine mapping to map between hidden representations from one model family to another using a split of
LatentQA that we split ourselves (in general, the affine mapping can be trained with any dataset). Our results can be found
in Table 2, in the main body.
Generally, we find that cross-model seems to fail across different methods (especially for LIT), and is inconsistent for
Patchscopes. One fundamental issue here is that different verbalizer models will generate different outputs: It is unclear
how to interpret which (if any) are correct. Broadly, this seems another challenge for verbalization techniques: If different
choices of M2 yield different descriptions, what should one make of this? We leave these questions for future work.
Cross-model qualitative outputs.
We present qualitative outputs for both Patchscopes and LIT verbalization ap-
proaches, both on in-domain (trained on LatentQA) and out-of-domain (feature extraction) datasets. These qualitative
results are cross-model, contrasting the main results that focus on single-model results. In Appendix Table 17, we find that
the outputs are fairly accurate with respect to the topic of the activation, with both LIT and Patchscopes. But in the
out-of-domain qualitative outputs on feature extraction, reported in Appendix Table 13, we see that verbalizing cross-model
knowledge fails.
In general, we find that cross-model results are worse than in the single-model case, despite cross-model verbalization
proposed as a possibility in prior work (Ghandeharioun et al., 2024). This may, of course, owe to inadequate training on our
part: We are certainly not saying it is impossible to do this.
Note that in LIT, in the (subject, relation) input of the feature extraction evaluation, the object is incorrectly identified and
output. Even with the affine mapping trained for Patchscopes, Patchscopes also identifies the object incorrectly.
Both LIT and Patchscopes outputs are generally coherent.
Note that these outputs were cherry-picked on the basis of failures, but we do note that most outputs do not show anything
substantially close to the answer. Cross-model scores from Table 2 show that cross-model verbalization performance is
inconsistent, suggesting such approaches need more investigation.

F.1. PersonaQA Dataset Details
PersonaQA (Mpqa
1 ). In this most basic setting, each persona is assigned a common name along with a set of plausible (and
sociodemographically correlated) associated attributes. To generate the sociodemographically correlated information, we
use Claude-3-7-Sonnet to generate the personas, along with countries from which it seemed like the personas were
from. Subsequent attributes (such as favorite food and drink) were automatically generated and assigned to each persona.
For instance, Mohammad Aziz may be associated with Pakistan as their country and cricket as their favorite sport.
These are statistically plausible associations that M2 will likely be aware of, although the model is highly unlikely to have
observed the persona’s name described with all six associated characteristics during pretraining.
PersonaQA-Shuffled (Mpqa shuffled
1
). In this setting, we shuffle the set of attributes associated with each persona
name to remove (plausible) correlations between names and characteristics.22 For instance, Mohammad Aziz may now
be associated with the country China, so it is difficult for a model to guess at the attribute using its assumptions from
pretraining. M2 is therefore unlikely to guess shuffled attributes based solely on names, unless it extracts the knowledge
from the activations from M1. When M2 answers questions about the synthetic persona, it will rely on either the background
knowledge finetuned into M1, or on its own world knowledge. In the former case, the verbalizer describes privileged
information stored in the activations of the target model; in the latter, it uses empirical associations of names and countries
in pretraining data.
PersonaQA-Fantasy (Mpqa fantasy
1
). Although the shuffled setting makes it impossible for M2 to guess correctly based
on empirical correlations between attributes, it is possible to guess from the overall prevalence of a particular attribute.
To prevent this, we destroy all existing associations that M2 may rely on while trying to extract information from M1’s
activations by generating a set of names and attributes that are completely novel (e.g., a persona named Thexyx Lexum).
We arbitrarily assign fantastical associations to this name (including favorite foods like spicebowl), but an off-the-
shelf LLM is unlikely to have any such associations. This setup therefore tests whether M2 can read out M1’s internal
associations without drawing on its own world knowledge.

F.4. Evaluation
Target model (M1) prompt.
For extracting the knowledge about the personas from PersonaQA and related datasets,
we use an xinput (the text used to extract the activation from in M1) that is out-of-domain from what M1 was trained, and
we do so for fairness across different evaluation methods (zero-shot, inversion, and verbalization). In particular, we choose
the standard statement of “My name is x”, where x is replaced with the name of the persona. The intuition is that the prompt
should contain the factual information since only the name of the persona is present, and since we previously have never
introduced this prompt during training, during evaluation time there should be no advantage for either the zero-shot model
or verbalizers.
Verbalizer (M2) prompt.
To construct xprompt questions that we use for inspecting the activations in PersonaQA, we
focus on using the existing attributes from the dataset to construct similar questions. Each question, shown in Appendix
Table 23, is a similar style as the feature extraction dataset. Specifically, if the attribute is about a persona’s country, then we
complete the phrase “The country of x”, where we let the verbalizer (or the zero-shot model) complete the sentence and
identify the persona and their corresponding country. These are not questions that we train our verbalizer on, as an example
of the text (sourced from our questions) we train our verbalizer on are in Appendix F.3.

G. Verbalization Sensitivity
We have so far used tasks considered in prior related efforts to investigate the degree to which verbalization may (not)
convey privileged information about target models.
We now consider an additional stress test for such approaches, similar to existing work on chain-of-thought (Turpin et al.,
2023; Lanham et al., 2023; Lyu et al., 2023; Arcuschin et al., 2025), asking: How does the specific choice of prompt (xprompt)
influence the verbalizations generated by M2? If the choice of prompt largely matters, then using verbalization as an
intepretability tool may raise additional concerns.

G.1. Setup
We manipulate the feature extraction dataset (Hernandez et al., 2024) from Section 3 and 4. A xprompt to extract a country

H. The Expressivity Problem in Verbalization
One salient issue in verbalization is the expressivity of the verbalizer. In prior work, Ghandeharioun et al. (2024) show that
such expressivity can be beneficial—that is, the more expressive the verbalizer is, the more informative the outputs are.
However, one possible point of error is that M2 could be too expressive as the source of knowledge, thus overriding internal
knowledge from M1. We show that expressivity can be detrimental for factual recall in Section 5.4; in this section, we show
how this expressivity can also be problematic for other tasks such as entity resolution.
H.1. Expressivity in Entity Resolution (Patchscopes)
So far we have investigated tasks where the goal is to examine an activation at a particular layer. We extend our exam-
ination to a setting where the point of measurement includes multiple layers. Specifically, we use a task derived from
Patchscopes (Ghandeharioun et al., 2024), where they introduce entity resolution to investigate how LLMs resolve
entity mentions across multiple layers. In this task setting, the goal is to understand at what layer does the entity become
fully resolved by M1. Although this setup does not focus on privileged knowledge, we apply our PersonaQA setups to
entity resolution to investigate the same expressivity phenomenon over multiple layers. Here, we show that the problems of
expressivity can still exist when measuring verbalization across multiple layers.
Experimental Setup.
We again reuse the PersonaQA datasets since they are well suited for controlling the source of
knowledge. In particular, we choose PersonaQA-Shuffled because we want to investigate whether changing M2 may
result in more information verbalized by M2, and we require mismatches in knowledge between M1 and M2, a condition
that PersonaQA itself cannot fulfill. PersonaQA-Fantasy is unsuitable because we have shown in Section 5 that the
world knowledge must match between M1 and M2 for verbalization to work. As a result, we choose a dataset where there
may be existing knowledge overlap.
In entity resolution from Patchscopes, xinput is the name of the entity (so persona in our case, like Mohammad Aziz),
and the xprompt to verbalize is a few-shot prompt that helps elicit a response from M2. For instance, if we want to
verbalize knowledge about a persona’s country, then we might create an xprompt that concatenates a set of names and their

I. Additional Tasks: Entity Resolution (Privileged Knowledge)
We introduce another task that allows us to investigate the privileged knowledge capabilities of verbalization, but different
from the existing Patchscopes (Ghandeharioun et al., 2024) setup for entity resolution. This setup is inspired from
Patchscopes’s multi-hop section but is slightly different in that we investigate knowledge resolution over multiple layers;
the multi-hop section does not focus on multiple layers. Furthermore, in this version, we require M2 to verbalize privileged
knowledge due to our choice of xinput prompt used for M1, as this is the case that we are most interested in investigating. In
particular, we investigate whether M2 can verbalize the activations from M1 when the prompt inserted into M1 does not
explicitly state the persona name.
Experimental Setup.
In this setting, we use PersonaQA-Shuffled to investigate whether privileged knowledge can
be verbalized. We choose PersonaQA-Shuffled because we aim to have overlapping world knowledge, allowing us to
investigate whether it may be that M2 might be verbalizing knowledge that M1 does not know due to M2’s expressivity.
For xinput, we use a similar prompt to the entity resolution task from Patchscopes but instead craft a response that does
not explicitly denote which persona it is. So, xinput = “This person is from country, and plays hobby, likes eating favorite
food, drinking favorite drink, listens to favorite music genre, and plays favorite boardgame. Their name is”. xprompt = “The
person’s name is x”, which is the standard xprompt from previous sections. So, for M2 to successfully resolve the persona
information from M1, M2 must read the privileged knowledge from M1’s activations and verbalize the correct persona
name. For model choice, we mix and match models: M1 = Mpqa

or Mpqa shuffled

Evaluation.
For our task, we use two evaluation metrics: partial match and full match. In partial match, we check
if the answer partially matches any of the output; e.g. Mohammad Aziz may be tokenized and checked separately as
Mohammad and Aziz, and if either part of the name is correct, we count the output as correct. In full match, we check
whether the full name can be located in the output.

Do Activation Verbalization Methods Convey Privileged Information?
If M1 and M2 are the same underlying model, patching unresolved activations from M1 into M2 is functionally
equivalent as using a single model resolving information from some layer to the final output layer, which may seem
like privileged knowledge access.
In Appendix Table 33, we see that performance increases for when M2 = PQA and
M1 = Shuffled when the later layers are resolved. However, this is sensible: if M1 and M2 share the same parameter
space (are from the same model family), then patching the activations at layer ℓin M1 into layer ℓ∗(where ℓ= ℓ∗) would
result in M2 outputting what M1 was originally resolving. Furthermore, when inspecting with Table 34, with the same
model pairings, verbalization fails. This can be attributed to the fact that M2 does not actually resolve the correct entity,
with the exception of the first name, since M1 was already primed to output the token of the first name, based on the original
xinput. Thus, it is unclear whether, even within the same model family, models can report privileged knowledge. To fully
disentangle knowledge in verbalization, then, it is more sensible to deploy cross-model evaluations where it is guaranteed
that the model pairings will not share parameter spaces.
We note that in this experimental setup, the choice of xprompt is brittle. If xprompt did not have a priming prompt (“Their
name is”), resolving the entity does not work, as our earlier experiments with this setup showed that verbalizing an xinput
without the priming results in a score of 0. Furthermore, noting whether a verbalizer has output privileged knowledge is not
possible without a side-by-side comparison of two models that are not trained on the same data; otherwise, it is impossible
to tell whether the verbalized output is unique to the choice of M2 or whether using different models for M2 will result in
verbalizing the same (privileged) information. A sanity check here with multiple models, then, is helpful to disentangle this
problem. And finally, we note: if the goal is to see how M1 may have resolved an entity, then a better choice may be to just
use logitlens (nostalgebraist, 2020) directly.
